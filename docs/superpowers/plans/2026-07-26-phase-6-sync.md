# Phase 6: GitHub Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Continuous multi-device sync through the private `organizedchaos-data` repo (spec §8): every mutation lands remotely within seconds, a fresh device hydrates from a PAT paste, conflicts resolve entity-level newest-wins, and git history becomes point-in-time backup.

**Architecture:** Three layers under `src/lib/sync/`: `files.ts` (pure serialization: AppState ⇄ `active.json` / `logbook-<year>.json` / `meta.json`), `merge.ts` (pure entity-level newest-wins with tombstone rules), `engine.ts` (orchestration: debounced push, pull-on-focus, sha-conflict retry) over `githubClient.ts` (typed Contents-API wrapper). The engine takes the client as a constructor arg so unit tests inject a fake; e2e stubs `api.github.com` with Playwright route interception — no network, full protocol coverage. **CORS pre-verified 2026-07-26**: `access-control-allow-origin: *`, preflight allows `Authorization` + PUT.

## Global Constraints

- The PAT lives ONLY in the device kv (`syncToken`) — never in synced files, never in state exposed to serialization, never logged.
- Local remains source-of-usability: sync failures must never block or corrupt local mutations.
- Every remote write sends the known `sha` (optimistic concurrency); on 409/422 conflict: re-pull → re-merge → retry (max 3, then surface error status).
- Tombstones older than 90 days are dropped at serialization time (spec §3).
- kv singletons (`currentTask`, `settings`) gain an `updatedAt` stamp for merge; reads stay back-compatible with the pre-Phase-6 plain shapes.

### Task 2: merge (TDD — this is the correctness heart)

**Files:** create `src/lib/sync/merge.ts`, `src/lib/sync/merge.test.ts`.

```ts
export interface MergeResult { merged: RemoteSnapshot; localChanged: boolean; remoteChanged: boolean }
export function mergeSnapshots(local: RemoteSnapshot, remote: RemoteSnapshot): MergeResult;
```

Rules: per entity id, newest `updatedAt` wins wholesale (no field merging); present-only-on-one-side survives (tombstones included — that's how deletes propagate); equal timestamps prefer the tombstoned/completed version (deterministic, biases toward "done"); `currentTask` and `settings` by their stamps. `localChanged` = merged differs from local (need to persist locally); `remoteChanged` = differs from remote (need to push).

Tests: newer-local wins / newer-remote wins; delete propagates over stale edit; edit newer than tombstone resurrects; one-sided adds both directions; equal-ts tombstone bias; currentTask stamp comparison incl. null-with-newer-stamp beats set-with-older (clearing propagates); `localChanged`/`remoteChanged` truth table (identical → both false); merge is commutative on outcomes (A⊕B == B⊕A for the merged set).

### Task 3: GitHub client + sync engine (TDD with fake client)

**Files:** create `src/lib/sync/githubClient.ts`, `src/lib/sync/engine.ts`, `src/lib/sync/engine.test.ts`.

```ts
// githubClient.ts
export interface SyncConfig { owner: string; repo: string; token: string }
export interface RemoteFile { json: unknown; sha: string }
export class GithubClient {
  constructor(cfg: SyncConfig);
  getFile(path: string): Promise<RemoteFile | null>;            // null on 404
  putFile(path: string, json: unknown, sha?: string): Promise<string>; // returns new sha; throws ConflictError on 409/422-sha
  checkAuth(): Promise<{ ok: boolean; error?: string }>;        // GET repo, distinguishes 401/404
}
export class ConflictError extends Error {}
// content is base64 of pretty-printed JSON (git diffs stay reviewable)

// engine.ts
export type SyncStatus = 'disabled' | 'idle' | 'syncing' | 'error' | 'offline';
export interface ClientLike { /* getFile/putFile structural subset */ }
export class SyncEngine {
  constructor(deps: {
    client: ClientLike;
    loadLocal: () => Promise<RemoteSnapshot>;
    saveLocal: (snap: RemoteSnapshot) => Promise<void>;
    debounceMs?: number;                       // default 4000; tests pass 0
  });
  status: SyncStatus;                          // $state (engine lives in .svelte.ts? no — plain fields + subscribe cb)
  lastSyncAt: number | null;
  onStatus?: (s: SyncStatus) => void;
  requestSync(): void;                         // debounced full cycle
  syncNow(): Promise<void>;                    // immediate full cycle (init/focus/manual)
}
```

Cycle: read remote files (tracking shas) → `fromFiles` → merge with local → if `localChanged` saveLocal(merged) → if `remoteChanged` `toFiles` + put each changed file with its sha → ConflictError → refetch/remerge/retry (≤3). File-level change detection: only PUT files whose serialized JSON differs from the remote payload.

Engine tests (fake in-memory client): first-sync-to-empty-remote pushes all files; pull-only when remote newer; push-only when local newer; conflict on put → retry succeeds with merged content; three conflicts → status 'error'; debounce coalesces bursts (fake timers); network throw → 'offline', local untouched; unchanged state → zero puts.
